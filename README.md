# Cliptone

A cross-platform JUCE 8 synthesizer plugin. The project is declared in `cliptone.jucer`
(Projucer). The desktop build is driven by a hand-maintained CMake script that fetches JUCE via
CPM; the Android build uses Projucer's exported Gradle project.

## What it does

A touch-first, clip-based MIDI workstation. The workflow follows the session / arrangement
model described in public DAW documentation. Everything here is original code; see
`docs/rea/` for the behaviour checklist and the design-decision ledger.

- **Session**: clip grid with scenes, launch quantization, launch modes, follow actions, legato,
  stop buttons, MIDI recording (overdub, count-in, record quantization).
- **Clip**: piano-roll note editor (grid / snap / fold, velocity lane, loop brace, quantize,
  transpose, duplicate loop), clip name and colour, MIDI export.
- **Arrange**: timeline with arrangement record, Back to Arrangement, loop brace, volume / pan
  automation.
- **Device**: per-track Sampler / Synth / Drums instrument plus a filter and compressor insert.
- **Mixer**: volume, pan, activator, solo, arm, meters, two returns (delay, reverb) with pre/post.
- **Transport**: bars.beats.sixteenths position, tap tempo, metronome, swing, host sync.
- **Sets**: save / open (`.cliptone`, XML), stored as plugin state too, plus undo / redo.

## Prerequisites

- CMake 3.22+
- A C++17 toolchain (MSVC / Clang / GCC)
- Network access on first configure (CPM downloads JUCE)

Android also needs:

- Android Studio + Android NDK
- The desktop CMake configured at least once. The Projucer-exported Android CMake references JUCE
  sources from `Builds/desktop/cmake-build-debug-visual-studio/_deps/juce-src/`, so CPM must have
  populated that path first.

## Build (desktop)

```sh
cmake -S Builds/desktop -B Builds/desktop/cmake-build-release-visual-studio
cmake --build Builds/desktop/cmake-build-release-visual-studio --config Release
```

CLion users can just open `Builds/desktop/CMakeLists.txt`.

Artifacts:

- `Builds/desktop/cmake-build-release-visual-studio/Cliptone_artefacts/Release/VST3/Cliptone.vst3`
- `Builds/desktop/cmake-build-release-visual-studio/Cliptone_artefacts/Release/Standalone/Cliptone[.exe|.app]`

## Tests

```sh
cmake -S Builds/desktop -B Builds/desktop/cmake-build-release-visual-studio -DCLIPTONE_BUILD_TESTS=ON
cmake --build Builds/desktop/cmake-build-release-visual-studio --target CliptoneTests --config Release
# then run the CliptoneTests executable from the build's CliptoneTests_artefacts folder
```

Headless sequencer / mixer / device / serializer tests (`tests/SequencerTests.cpp`).

## Build (Android)

Open `Builds/android/` in Android Studio, or run `Builds/android/gradlew assembleRelease`. The
Gradle project and `Builds/android/app/CMakeLists.txt` are generated by Projucer — re-save
`cliptone.jucer` to regenerate after changing modules, exporter settings, or the file list.

## Notes on JUCE version

`Builds/desktop/CMakeLists.txt` pins JUCE 8.0.12 via CPM. If that tag is not available on
`juce-framework/JUCE`, bump `GIT_TAG` / `VERSION` to the current 8.0.x patch.
