# Lye — Claude notes

Lye is a **separate app** from Androtone (the rest of this repository). It is a clean-room
recreation of Caustic 3 for Android, built with JUCE 8.0.12. Do not share code, build files, or
docs with Androtone, and do not change anything outside `lye/` when working on Lye (the only
exception is its CI workflow, `.github/workflows/lye.yml`).

Read `docs/spec.md` (what we are recreating) and `docs/roadmap.md` (where we are) before
non-trivial changes. Clean-room rule: work from observed behaviour and the public manual only;
never decompile Caustic or copy its assets.

## Layout

- `CMakeLists.txt` — desktop build: `Lye` app and `LyeTests`. CPM fetches JUCE into
  `external/JUCE` (git-ignored; fixed path so the Android export can use it too).
- `Lye.jucer` — Projucer project, used only for the Android export.
- `Builds/Android/`, `JuceLibraryCode/` — generated by Projucer from `Lye.jucer`; do not edit.
- `source/core/` — the engine. No GUI or audio-device code: it is compiled into both the app and
  the tests.
  - `Transport` — beat ↔ sample mapping; `Pattern` / `PatternPlayer` — pattern → MIDI;
    `Machine` — instrument interface; `Engine` — rack, mixer, audio callback;
    `machines/` — machine implementations.
- `source/app/` — the JUCE app shell and UI.
- `tests/` — Catch2 tests; `TestHelpers.h` has the offline renderers.

## Build and test (desktop)

```
cmake -S lye -B lye/build
cmake --build lye/build --target LyeTests
ctest --test-dir lye/build --output-on-failure
cmake --build lye/build --target Lye
```

Run the tests before every push; CI runs them on Linux.

## Build (Android)

Configure the desktop CMake once (so `external/JUCE` exists), then open `lye/Builds/Android` in
Android Studio or run `./gradlew assembleDebug` there.

## Adding files

- Add to `CMakeLists.txt` (`LYE_CORE_SOURCES` for engine code, `Lye` target for app code, `LyeTests`
  for tests).
- Add engine and app files (not tests) to `Lye.jucer`, then regenerate the Android project:
  `Projucer --resave lye/Lye.jucer`.

## Conventions

- Engine code is real-time code: no allocation, locks, or I/O in `Engine::process` and below.
- Musical time is in beats (double); sample positions are `int64_t` from `Transport`.
- New behaviour comes with an offline test that fails without it.
